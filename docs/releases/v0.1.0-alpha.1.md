# Lyvune v0.1.0-alpha.1

**The first public alpha.** It is for people who are happy to try a new music server and report what breaks. Back up
your data before every update, and do not expose it to the internet without a reverse proxy
([how](../DOCKER.md#open-it-from-outside-a-reverse-proxy)).

Lyvune is a self-hosted music server and streamer with word-by-word karaoke lyrics. It started as a fork of
[Navidrome](https://www.navidrome.org) and keeps its code, its licence and its copyright notices; see
[Credits](#credits-and-licence).

## What you get

- **A rewritten web interface**: new player, layout, album, artist and playlist pages, in the Lyvune colours, with two
  themes (*Lyvune* and *Lyvune Black (OLED)*). Playback is owned by one audio element outside the page, so moving around
  never interrupts the music. Scroll over the volume bar to change the volume.
- **A lyrics engine**: it looks for missing lyrics (LRCLIB; KuGou, NetEase and QQ Music, which are off for saving by
  default; Musixmatch with your own key), prefers the lyrics files you already have, and lets you override, lock and undo.
  Word-by-word karaoke is shown when a source really has word timing, and is never invented. Found lyrics can be saved
  next to the audio as `.lyrics.json`, per provider and under your control. Audio files are never modified.
- **Romanization** in the player, with one button, for Japanese, Chinese, Korean, Greek, Cyrillic and Arabic lyrics
  (made in your browser, approximate), with two styles for Japanese (doubled vowels or macrons).
- **Word timing for Subsonic clients**: `getLyricsBySongId` with `enhanced=true` returns it, and the server announces
  `songLyrics`.
- **Everything Navidrome had**: library scanning, the Subsonic and OpenSubsonic API, users, playlists, transcoding with
  ffmpeg, the jukebox with mpv.
- **No telemetry.** The anonymous insights collector is off by default, and so is the sign-in background from
  navidrome.org. Lyvune asks other services only for what you ask for (lyrics providers, Deezer for artist information);
  `ND_ENABLEEXTERNALSERVICES=false` turns even that off.
- **A Docker image** that runs as an unprivileged user, has a health check, keeps all its data in one folder and stops
  cleanly.

## Install with Docker

You need Docker with Compose and Buildx. The image is `ghcr.io/tian-mc/lyvune:0.1.0-alpha.1`, for `linux/amd64` and
`linux/arm64`.

```sh
git clone --branch v0.1.0-alpha.1 https://github.com/Tian-MC/lyvune.git
cd lyvune
cp .env.example .env
```

Open `.env`, set `LYVUNE_MUSIC_DIR` to your music folder and add the line
`LYVUNE_IMAGE=ghcr.io/tian-mc/lyvune:0.1.0-alpha.1`. Then:

```sh
docker compose pull
docker compose up -d --no-build
docker compose ps          # wait for "healthy"
```

Open <http://localhost:4533>; the first person to open it creates the administrator. Your music is mounted read-only.
To let Lyvune save lyrics next to your files, see [Your music and lyrics](../DOCKER.md#your-music-and-lyrics).

To check what you pulled: `docker buildx imagetools inspect ghcr.io/tian-mc/lyvune:0.1.0-alpha.1` shows the digest and
the platforms, and the digest is also in the release page.

## Coming from Navidrome

Nothing has to be migrated. Put the same data folder, or a copy of it, under Lyvune: `navidrome.db` is used as it is and
`navidrome.toml` is read when there is no `lyvune.toml`; `ND_` variables keep working. **Work on a copy first**, and read
[Coming from Navidrome](../DOCKER.md#coming-from-navidrome): Lyvune updates the database the first time it opens it,
and that is one-way, so keep the folder you copied from.

## Updating, backup and going back

```sh
docker compose exec lyvune lyvune backup create       # first, a backup
# set LYVUNE_IMAGE in .env to the new version
docker compose pull && docker compose up -d --no-build
```

To go back, restore the backup you made first and run the old image; the steps are in
[Updating, and going back](../DOCKER.md#updating-and-going-back). Running an older version on a newer database is not safe.

## Known limits

- **It is an alpha.** Expect rough edges, and database changes between alphas.
- **arm64**: see the line "Tested on" below for what was actually run on ARM.
- **Windows, macOS, `.deb` and `.rpm` packages are not part of this release.** Only the Docker image is. The Linux
  packaging that came with Navidrome still carries Navidrome's names and is not published.
- **Lyrics providers**: Lyvune does not grant any right to the lyrics it finds. No provider's terms on keeping lyrics
  could be verified, so saving them is your decision; only LRCLIB is on by default. Musixmatch needs your own key.
- **Romanization is approximate**, made in the browser from dictionaries, and meant as a reading aid.
- **The server still presents itself to Subsonic clients as `navidrome`**, because clients recognise it, and the features
  it has, by that name.
- **The new interface text is translated to English and Italian.** Other languages show English for it.
- The Windows test job in the project's CI has not been shown to pass on every run yet.

## Tested on

The Docker image is tested by `scripts/docker-smoke-test.sh`, which builds or pulls it, starts it and checks the web
interface, accounts, the Subsonic API, scanning, streaming, an MP3 transcode, lyrics (saved and read back, and refused on
a read-only library), the health check, a restart, a clean shutdown and a migration from a Navidrome database.

- `linux/amd64`: tested on a real Docker host (Arch Linux), and on a GitHub runner.
- `linux/arm64`: not tested yet (this line is completed before the release)
