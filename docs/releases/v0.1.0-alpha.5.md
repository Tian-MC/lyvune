# Lyvune v0.1.0-alpha.5

**More songs get word-by-word karaoke, and a provider's rate limit no longer stops a library-wide job.** It is still an alpha: back up your data before every update.

## What changed

- **More karaoke found, measured.** On 50 real recordings (English, Japanese, Chinese, Korean, Italian, Spanish, French, German, Portuguese, metal) the word-timed lyrics taken automatically went from **82% to 92%**; any lyrics stayed at 98%. KuGou went from 35 to 43 of 50 tracks, NetEase from 26 to 29, QQ Music from 24 to 25. The causes, each fixed and tested:
  - A featuring credit inside brackets (`Get Lucky (Radio Edit - feat. …)`) was cut together with its closing bracket.
  - Traditional and simplified Chinese did not compare (`陳奕迅` and `陈奕迅`), and KuGou finds nothing for a traditional query. Han characters are now compared in simplified form, from the Unicode Han Database, and Chinese services are asked in simplified Chinese. Japanese is sent as it is.
  - An artist written with another name in brackets (`BTS (防弹少年团)`) is now one artist.
  - A subtitle or note on one side only (`MALAMENTE (Cap.1: Augurio)`, `任性（电视剧《难哄》主题曲）`) matches when the length agrees within 2 seconds.
  - KuGou, NetEase and QQ Music are searched for the bare title, and KuGou's search, which comes back empty at random, is asked again in another form.
- **A wrong version is less likely to be taken.** A title with words added (`Despacito 缓缓`, a Chinese cover) was verified at 0.91 for *Despacito*. It is now only listed, never chosen automatically.
- **A provider's rate limit no longer stops a bulk job.** Before, one rate limit from one provider ended the whole job ("A provider asked to slow down. Run it again in about 1s"). Now the job:
  - waits for the time the provider asked (at least 5 seconds, doubling for limits in a row, at most 10 minutes) and goes on by itself;
  - puts the refused track back in the queue instead of counting it as failed, so no track is lost and finished tracks are never redone;
  - stops only after 8 refusals in a row, naming the provider, with the work done kept;
  - shows which provider it waits for, when it starts again, and how many times it waited.
  Providers are also asked more slowly for a while after they refuse.

Your lyrics files, locks, offsets, sidecars and the settings are unchanged.

## What this does not do

- A title in another script (`Gurenge` and `紅蓮華`) is not matched: matching on artist and length alone could give the lyrics of another song.
- Two live performances of one song a few seconds apart cannot be told apart from the tags.
- While one provider is limited, the whole job waits, so results stay complete. A long wait pauses the job for that long.
- The services vary from one run to the next: the measurement is a sample, not an exact figure. The method is in `LYRICS_PROVIDERS_RESEARCH.md`.
- Musixmatch word timing is read only through the official API with your own key, and has not been verified against the live service. No other key-less source is used.

## Updating, backup and going back

There are **no database changes** in this release.

```sh
docker compose exec lyvune lyvune backup create       # first, a backup
# in .env: LYVUNE_IMAGE=ghcr.io/tian-mc/lyvune:0.1.0-alpha.5
docker compose pull && docker compose up -d --no-build
docker compose ps                                      # wait for "healthy"
```

To go back, set `LYVUNE_IMAGE` to `ghcr.io/tian-mc/lyvune:0.1.0-alpha.4` and run the same two commands. Details: [Updating, and going back](../DOCKER.md#updating-and-going-back).
