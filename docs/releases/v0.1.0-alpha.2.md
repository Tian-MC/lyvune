# Lyvune v0.1.0-alpha.2

**Translations no longer reach your music player unless you ask for them.** This alpha fixes a problem with external
players such as Symfonium and Feishin, which showed the machine translation that QQ Music, KuGou and NetEase send with
the original lyrics, and gave no way to hide it. It is still an alpha: back up your data before every update.

## What changed

- **Provider translations are off by default.** QQ Music, KuGou and NetEase stay available. When lyrics are found or
  upgraded automatically, the translation track is no longer kept; the original lyrics, the **word-by-word karaoke
  timing**, the **romanization** and the provider credit are kept as before.
- **Two new administrator settings** (Lyrics settings), both off by default:
  - *Include provider translations automatically*: keep the provider's translation when lyrics are found or upgraded.
  - *Send translations to external players*: let the Subsonic/OpenSubsonic and Jellyfin lyrics endpoints return
    translation tracks.
- **Better behaviour in Symfonium, Feishin and other OpenSubsonic clients.** `getLyricsBySongId` (with or without
  `enhanced=true`), `getLyrics` and Jellyfin now return the `main` and `pronunciation` tracks and no `translation`
  track, without changing anything in the player. This also covers lyrics you saved earlier or placed next to your
  files (`.lrc`, `.ttml`, `.lyrics.json`).
- **Your lyrics files are not touched.** Nothing is rewritten or deleted: the translations already in your
  `.lyrics.json` files stay there, and turning *Send translations to external players* on brings them back at once.

Settings saved by an earlier version load with both new settings off; your other settings are unchanged.

## Things to know

- **The Lyvune web player follows the same switch.** It reads the same endpoint, so with *Send translations to external
  players* off it shows no translations either. Turn the setting on to see them again.
- A search made by hand in the lyrics manager still shows the provider's whole result.
- A translation written inside a main lyric line (as opposed to a separate translation track) is not removed.
- The new settings text is in English only.

## Updating, backup and going back

There are **no database changes** in this release.

```sh
docker compose exec lyvune lyvune backup create       # first, a backup
# in .env: LYVUNE_IMAGE=ghcr.io/tian-mc/lyvune:0.1.0-alpha.2
docker compose pull && docker compose up -d --no-build
docker compose ps                                      # wait for "healthy"
```

To go back, set `LYVUNE_IMAGE` to `ghcr.io/tian-mc/lyvune:0.1.0-alpha.1` and run the same two commands. The two new
settings are stored beside the others and are ignored by the older version. Details:
[Updating, and going back](../DOCKER.md#updating-and-going-back).

## What was checked

The Go and web tests, the linter, and the Pipeline passed on the commit before the tag. The image is tested on `amd64`
and on a native `arm64` runner before it is pushed, and again after, pulled by its digest. Not tested on a real ARM
board.
